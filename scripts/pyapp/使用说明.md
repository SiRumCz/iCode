# iCode 二进制使用说明

本说明随发布包一并提供。解压后即可运行，**不需要**在机器上预装 Python。

发布页示例：<https://gitcode.com/michaelling/iCode/releases>（按 tag 下载对应版本）。

## 选哪个包？

**日常使用请优先选带 `-full-` 的包**（全量依赖版）。精简版体积更小，但首次启动必须联网从 PyPI 装依赖，且可能与本仓库锁定的 `openjiuwen`（Git fork）不一致。

### 按平台

| 文件名包含 | 适用环境 |
|------------|----------|
| `linux-x86_64` | x86_64 Linux（常见服务器 / 桌面） |
| `linux-aarch64` | ARM64 Linux |
| `macos-aarch64` | Apple Silicon（M 系列）Mac |
| `macos-x86_64` | Intel Mac |
| `openjiuwen_icode-*-py3-none-any.whl` | 已有 Python 时用 pip/uv 安装（可选，开发向） |
| `icode-*.vsix` | VS Code / OpenVSX 扩展（与二进制同版本） |
| `SHA256SUMS.txt` | 发布目录校验和 |

### 按依赖是否内置（看文件名有没有 `-full-`）

| 文件名形态 | 类型 | 体积 | 首次运行 | 推荐 |
|------------|------|------|----------|------|
| `icode-<平台>-full-vX.Y.Z.tar.gz` | **全量依赖版（full）** | 很大（依赖全部打进包） | **可离线**，解压即用 | **是（默认选这个）** |
| `icode-<平台>-vX.Y.Z.tar.gz` | **精简版（slim）** | 较小（约几十 MB） | 需联网，从 PyPI 安装第三方依赖 | 仅在能稳定访问 PyPI、且能接受首次安装时 |

同一版本的对照示例（Linux x86_64）：

- 全量：`icode-linux-x86_64-full-v0.1.38.tar.gz`
- 精简：`icode-linux-x86_64-v0.1.38.tar.gz`
- macOS 示例：`icode-macos-aarch64-full-v0.1.38.tar.gz` / `icode-macos-aarch64-v0.1.38.tar.gz`

校验完整性可参考同目录的 `SHA256SUMS.txt`。

## 怎么用

两种包解压后用法相同（归档内可执行文件都叫 `icode`）：

```bash
# 推荐：全量版（注意选对平台）
tar -xzf icode-linux-x86_64-full-vX.Y.Z.tar.gz
# 或精简版
# tar -xzf icode-linux-x86_64-vX.Y.Z.tar.gz

./icode --help
./icode tui

# 可选：放到 PATH
mkdir -p ~/.local/bin
cp icode ~/.local/bin/
icode
```

Windows 发布包（若提供）解压后运行 `icode.exe` 即可。

常用入口示例：

```bash
icode                  # 交互 TUI（终端）
icode run -t "..."     # 无头跑任务
icode --help
```

## 精简版：首次运行在「安装」什么？

精简版二进制里已经嵌入了：

1. **CPython 运行时**（当前打包一般为 3.13）
2. **本版本的 `openjiuwen-icode` wheel**（产品包；命令行入口仍是 `icode`）

**第一次启动**时，PyApp 会在用户目录下的**私有环境**中完成自举（与系统 Python / Homebrew 无关）：

1. 解压嵌入的 Python
2. 用内置 pip 安装嵌入的 wheel
3. 从 **PyPI** 拉取第三方依赖（如 openai、textual、mcp、transformers 以及 `openjiuwen` 等）

因此你会看到一段时间的 Installing / 下载进度——装的是**应用依赖到 PyApp 私有目录**。  
**第二次及以后**一般会直接进入程序。

注意：本仓库开发依赖的 `openjiuwen` 来自 GitCode fork（见根目录 `README.md` / `pyproject.toml`）。精简版首次安装走 PyPI，**不一定**与发版时 lock 的 fork 提交一致；若出现缺模块或行为异常，请改用 **`-full-`** 包。

公司网络可设置镜像：

```bash
export PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple
./icode
```

## 全量版（`-full-`）：离线开箱

全量版在**打包时**已按仓库 `uv.lock` 把产品包及全部第三方依赖安装进嵌入的 Python，并设置运行时跳过安装：

- 解压后直接跑，**一般不再访问 PyPI**
- 包体显著更大，下载与分发更重
- 适合无外网、内网隔离或希望「一次下载即可用」的场景
- 与发版机上的依赖闭包一致，TUI / SDK 行为更可预期

## 注意事项

1. **选对 CPU 架构**，否则无法运行或需模拟器。
2. **按文件名区分 slim / full**，不要只看解压出的 `icode` 文件名（两种包内二进制同名）。
3. 精简版首次启动耗时与网络有关；全量版主要耗在下载发布包本身。
4. 精简版：不要删除 PyApp 缓存/安装目录后还期望「秒开」（默认在 `~/.local/share/pyapp/`）。
5. `.whl` 面向开发者；普通用户优先用对应平台的 **`-full-` `.tar.gz`**。
6. Linux 包面向常见 glibc 环境。

## 问题排查

- **精简版一直卡在安装**：检查网络 / `PIP_INDEX_URL`；或改下 **`-full-`** 包。
- **缺模块 / TUI 起不来（精简版）**：优先改用同版本的 `-full-` 包。
- **权限错误**：`chmod +x icode`。
- **macOS「无法打开 / 已损坏」**：若信任该来源，可执行  
  `xattr -d com.apple.quarantine icode`。
- **需要离线**：必须使用文件名含 `-full-` 的包。

更多开发向打包说明见仓库内 `scripts/pyapp/README.md`。
